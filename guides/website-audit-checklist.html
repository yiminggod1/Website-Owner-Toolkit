Website Audit Checklist: A Practical Pre-Publish Review

A practical website audit checklist covering titles, headings, links, images, canonicals, schema, indexability, and the fixes worth checking before launch.

A good audit starts with the page's purpose

A page audit is useful when it answers a practical question: can the intended visitor understand the page, can search systems discover and interpret it, and can the site owner maintain it without surprises? A checklist is more useful when it follows that order instead of producing dozens of disconnected warnings.

1. Check the title and main heading

Make sure the title describes the specific page rather than the whole site. The visible main heading should make sense when read without the rest of the navigation. Use the Meta Title Checker and Heading Checker to inspect these signals.

2. Review the description and page summary

A useful meta description is page-specific and written for people. It should explain the value of the page rather than becoming a list of keywords. Search engines can choose different snippet text, so treat the description as helpful metadata, not a guaranteed script.

3. Inspect canonical and indexability signals

Confirm that the canonical points to the URL you actually want represented. Then review robots directives for accidental noindex or broad crawler blocks. The Canonical Checker and Robots.txt Checker help with this page-level review.

4. Review images and links

Look for informative images that need meaningful alternative text, and make sure links have understandable text. Also check that your internal navigation leads to real destinations. The Image Alt Checker and Link Structure Checker are designed for this pass.

5. Check search and sharing metadata

Review Open Graph tags, structured data, and the page's likely search snippet. A valid JSON-LD block is not enough by itself; it should describe content that actually exists on the page. Use Open Graph Checker, Schema Validator, and SERP Preview.

6. Finish with the Website Audit

The Website Audit is best used as the final consolidated pass. Run it after individual checks so that the report becomes a confirmation layer rather than the only source of diagnosis.

What an audit cannot prove

A browser-first audit cannot replace server-side crawling, authenticated testing, complete redirect-chain inspection, real performance measurement, or human accessibility review. Treat every result as evidence for a next action, not as a certification.
