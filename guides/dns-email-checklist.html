DNS and Email Authentication Checklist for Website Owners

A practical guide to checking website DNS, mail records, SPF, DMARC, MX, and DKIM.

DNS connects names to services

A website owner may interact with DNS only during a domain setup, but the records control important services such as web hosting and email delivery. Looking at the public records can reveal what is currently configured.

Start with the records that answer your immediate question

A records commonly point a name to IPv4 addresses; AAAA records cover IPv6; MX records identify mail exchangers; TXT records often carry verification and email-authentication data. Use the DNS Lookup when you need to inspect a specific record type.

Check the mail foundation

For a domain that sends email, confirm that the expected MX records exist and that the published SPF and DMARC policies match your mail provider's instructions. The Email DNS Checker provides a quick browser-based first pass.

DKIM deserves provider-specific review

DKIM records normally depend on a selector chosen by the mail provider. The same domain can use different selectors for different services. If the default selector returns nothing, that does not automatically mean DKIM is missing.

DNS results are snapshots

Resolvers cache responses, and changes can take time to appear consistently. Compare the result with the configuration shown by your domain or email provider before deciding that a record is wrong.

Use the result as a troubleshooting aid

Public DNS inspection can show what the internet is currently being told, but it cannot explain every reason a mail message or website request might fail. Combine DNS checks with server logs, provider dashboards, and real request testing when troubleshooting.
